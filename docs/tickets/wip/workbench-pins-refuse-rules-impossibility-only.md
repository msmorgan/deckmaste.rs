# Pins refuse rules-impossibility only

Ruling (2026-08-22): the semantics layer accepts anything the Comprehensive
Rules make meaningful. A pin (`Unspellable … impossible` in
`idris/src/Experimental/Proofs*.idr`) refuses a term only when a rule makes it
meaningless — a category error or a contradiction — and its docstring names
that rule. "No card has written this" is never a reason to refuse: what English
prints is spelling-boundary knowledge, and a restriction that leaves a printed
card unrepresentable is the worst outcome. Authority:
`docs/memory/rulings/measurements-live-in-pins.md` and the overgeneration
clause of
[The kind index joins; union marking is spelling](../../decisions/kind-index-joins-union-marking-is-spelling.md).

The workbench has ~717 pins, many minted on the opposite doctrine ("a measured
zero is a pin"). This ticket reverses that.

## Phase 1 — classify every pin

For each pin, one of:

- **RULES** — the docstring names a CR rule under which the term is
  meaningless. Keep; verify the cite points the direction the claim needs.
- **STRUCTURAL** — the term is meaningless by the model's own algebra (a
  duplicate card type in a set; an order rider on a two-end disjunction; a
  verb that needs an agent used without one; `Quality \/ Outcome`). Keep; cite
  the rule if one exists.
- **CORPUS** — the only justification is a count or an absence ("0 of 440
  lines", "no card writes it", "single witness"). Widen the gate behind it
  and delete the pin.

The table (pin · file · class · rule or reason) lands in this ticket.

## Phase 2 — widen and delete, per file

For every CORPUS pin: admit the cell in the gate table it exercises, delete the
pin, and keep `idris/scripts/build` green. Where the gate was a constructor
index or a trimmed sum, restore the arm with the rules-correct shape (a
duration the CR states, an agent slot) rather than just admitting. Bench any
printed card the refusal had left out — Luxior first. Named first cases:

- `attachHeadOk Equipped PermanentW` → admitted ([CR#301.5]: creatures
  "unless an effect says otherwise"); `Equipped`/`Enchanted` are words for
  `AttachHost`, not constructors.
- `comparableBound` → a summed bound at every comparator.
- `admitsSpan CostModification` → admitted; `SpanUse` row renamed.
- `visibilityOk LookAt WholeHand` → admitted; its backwards [CR#402.3] cite
  fixed.
- `ConferringWord` → `SaddleW`/`AscendW`/`StoriedW`/`RenownW` restored with
  the durations [CR#702.171a,702.131a] and static shape [CR#702.195a] the CR
  states; `GainsDesignation` grows what it needs to carry them.
- `badZombieNoncreature` → the predicate "a Zombie that isn't a creature" is
  satisfiable by a **Kindred**: kindreds and creatures share one subtype list
  [CR#205.3m], so "Zombie" is a kindred subtype as much as a creature one
  (Nameless Inversion). Widen the predicate-side
  gate to the rule `subsFitLine` already applies to lines — a creature subtype
  needs Creature *or* Kindred — not to "any subtype anywhere".
- `badGroupAnyTarget` → "each of two targets" is a form [CR#115.4] lists;
  `anyTargetOkAt` admits maxima above one (Furious Reprisal, Pinnacle of Rage).
- `badAttackingUntapped` → [CR#508.4] taps nothing; an attacking token need not
  be tapped (Brimaz). Re-ground `ridersOk` on the rules it actually has.
- `DamageableTy` admits Battle ([CR#120.1a]) — a gate defect behind the
  legitimate `badDamageArtifact`, not a pin.
- **Loyalty is a `CounterKind`** ([CR#122.1] defines every counter as a marker
  modifying characteristics; [CR#122.1e] only says what the count indicates).
  Finding 567's refusal ("a characteristic's value, not a marker") is a
  modelling preference, not a rule. Mint `Loyalty` in `CounterKind` AND a
  `Loyalty` characteristic read through the possessed-characteristic path —
  Nahiri, the Unforgiving uses both ("enters with two fewer loyalty counters";
  "mana value less than Nahiri's loyalty"); the count-equals-loyalty link is
  lowering's. Re-bench Nahiri, Vivien's and Teferi's Talents, Bioessence Hydra.
- `badPutIntoExile`, `badSweepAcrossPlayers`, `badSweepAcrossOpponents`,
  `badGroupCommander`, `badNoHolderNegated`, `badBeforeAttackersEachPlayers`
  → deleted with their gate cells admitted.

This lands before the union-family redesign so its pins are classified once.

Summary
1. Counts: RULES 28, STRUCTURAL 52, CORPUS 36, UNCLEAR 0 (116 pins total; the CORPUS block is dominated by 12 `SpanOk` duration-vocabulary pins and 3 literal-zero `WrittenCount` pins).
2. Cites pointing the wrong way: `badAttackingUntapped` (l.577) — [CR#508.4] says an effect designating a creature attacking taps nothing, and [CR#508.1f]'s tap is declare-attackers-only, so the rule cited in `ridersOk` (Words.idr:3160) as "an attacking creature is tapped" argues against the gate. `badZombieNoncreature` (l.692) — [CR#205.3m] (creatures and kindreds share subtype lists) makes a noncreature Zombie real, against the [CR#205.1a] presupposition claim. `badStaticCant` (l.364) — [CR#611.2a] positively defines a durationless continuous effect ("it lasts until the end of the game"), so the "may not omit the span" law has the CR against it.
3. False premises with no cite at all: `badPutCountersGraveyard` (l.585) — `counterZone` already admits Exile (suspend time counters), so "counters live on the battlefield" is not the model's own law either; `badBecomesInGraveyard` (l.660) — "a graveyard card has no types to add to" is simply false.
4. Printed cards the refusals leave out: Brimaz, King of Oreskos ("create a 1/1 white Cat Soldier creature token with vigilance that's attacking", untapped) is refused by `badAttackingUntapped`; Nameless Inversion (Kindred Instant with changeling — a Zombie that is not a creature) is refused by `badZombieNoncreature`; the extremely common "deals N damage to target creature or planeswalker" is refused by the same `DamageRecipient` gate `badDamageDisjunctHead` exercises, even though that pin's own term (artifact or enchantment) is legitimately RULES-refused.
5. Gate-sharing warning for phase 2: `CounterHolder` (Words.idr:1657) backs both a CORPUS pin (l.585) and a RULES pin (l.594) — widening it for graveyard counters must re-guard `badRemoveCountersDead` on [CR#400.7] (new object on zone change) instead; likewise `DamageRecipient` and `DeedParticipant` need disjunctive-head support without admitting undamageable/non-participating types.

**Summary**

1. Counts: RULES 29, STRUCTURAL 32, CORPUS 54, UNCLEAR 0 (115 pins total). The CORPUS mass is concentrated in five attestation tables — `spanUse`/`admitsSpan`/`absentOk`, `eventUse`/`admits{Intercept,Hold,Trigger,Delay}`, `partUse`, `triggerWordOk`, `reflexEncloseUse` — whose constructor names (`Unattested`, `Unclaimed`, `EventUnclaimed`, `PartUnattested`, `EncUnattested`) are literally corpus-census buckets; every pin routed through them is corpus-justified by construction.
2. Cites pointing the wrong way (11): badStandingIntercept/badStandingPrevention ([CR#611.3] only permits static-generated effects; [CR#611.2] allows resolution-generated ones), badInterceptForAsLongAs ([CR#611.2b] *defines* the shape refused), badNextTimeWouldDie ([CR#614.3] never says a creature dies once), badSearchBattlefield ([CR#701.23a] reads "even if it's a hidden zone"), badSearchLibraryPosition/…Ordered ([CR#701.23f] licenses portion-searching), badInsteadReadsReplacedOutcome ×3 ([CR#614.6] does not stop a replacement reading the would-be event's magnitude), badGainLifeCost ([CR#119.7] presupposes gain-life costs), badTargetedCost ([CR#601.2c]+[CR#601.2h] show the ordering *works*), badPayBySacrificing ([CR#118.1] calls every cost "paid"), badDelayedUntilEndOfTurn ([CR#603.7b]'s "such as 'this turn'" is exemplary), badMoveCountersToGraveyard ([CR#122.1a] covers cards off the battlefield), badMoveAttackingUntapped (Words.idr's [CR#508.4] comment; [CR#508.4] never taps the entering creature).
3. Printed cards the refusals leave out: **Mana Leak** ("Counter target spell unless its controller pays {3}") and its whole family ("Return target creature to its owner's hand unless its controller pays {1}") vs badUnlessAnaphoricPayer; **Vampiric Tutor** ("Search your library for a card, then shuffle and put that card on top") vs badReadAfterShuffle; **Furnace of Rath / Boon Reflection**-shaped lines ("deals double that damage instead", "you gain twice that much life instead") vs the three badInsteadReads… pins; **totem armor** ("If enchanted permanent would be destroyed, instead …") vs badInterceptDestruction.
4. Two pins concede the gap in their own docstring: badGetsUntilLeavesBattlefield ("no … endpoint exists … in this duration vocabulary") and badReflexiveOnDeclinedMay ("[CR#603.12] licenses a negative reflexive, but this vocabulary has no such row"). Both are vocabulary rows to add, not refusals to keep.
5. Internal inconsistencies worth fixing with the widening: `searchableZone` refuses the battlefield "because it is public" while admitting the graveyard (also public per [CR#400.2]); `counterZone` refuses the graveyard while admitting exile, though [CR#122.1a] treats both alike; the `WrittenCount`-at-zero family (badZeroSlice, badMillZero, badDivideZero, badExileZeroCounters) is one discipline, but only badDivideZero has a rule ([CR#601.2d]) behind it.

**Summary**

1. Counts: **RULES 47, STRUCTURAL 17, CORPUS 50, UNCLEAR 0** of 114. The CORPUS mass concentrates in five attestation tables — `partUse`/`headerPossessorOk` (3), `eventUse` (7), `triggerWordOk` (5), `spanUse` (5), `negatable` (4) — plus `possessorOk` (3) and the closed count vocabularies `CapBound`/`NextUntapCount`/`capSubjectOk` (3); their value constructors are literally named `PartUnattested`/`EventUnattested`/`Unclaimed`.
2. Cites that point the wrong way: **badGameLossLookback** ([CR#603.10f] says game-loss triggers *do* look back — it licenses exactly what the pin refuses); **badHeldUntilBecomesUntapped**/**badHeldUntilTurnedFaceUp** ([CR#610.3] licenses "until [event]" with no restriction on the event); **badCostSubjectOnBattlefield** ([CR#609.2]'s "unless … clearly can apply only to objects in other zones" reads *toward* the spell reading); **badUntilEndOfCombatStep** ([CR#511.2] names both moments precisely rather than denying one).
3. Cites that are on-topic but do not establish meaninglessness: the five "At" pins ([CR#603.2b] is about *when* "at the beginning of" fires — [CR#603.1] lists When/Whenever/At with no event split); **badFlipEvent** ([CR#710.1a] describes the flip card's frame, not the absence of a flip event); **badTargetedOutcomeGate** ([CR#115.1d] is the *triggered*-ability subrule — the right cites are [CR#115.1,115.1a..115.1c] with [CR#604.1]); **badTurnFaceDownGraveyard** ([CR#708.7] is about turning face *up*; [CR#110.5] is the biting rule); **badDisagreeingZeroPump** ([CR#613.4c] is the layering rule, silent on sign spelling); **badInterceptBecomesBlocked** ([CR#509.1b] describes restrictions, which does not exclude replacement).
4. Printed cards the refusals leave out: **badMustBlockNoPatient** is the clear defect — "Target creature blocks this turn if able." is printed on a dozen-plus cards (Bewitching Whispers and others), yet `deonticPatientOk RequireT Block Agent = PatientRequired` refuses it. **badMustAttackWithPatient**/**badForbidAttackWithPatient** refuse the whole attack-patient cell, which excludes goad's own printed reminder "attacks a player other than you if able" [CR#701.15b] (only the *creature* patient is rules-impossible [CR#506.3]). **badWindowDuringYourEndStep** is contradicted in spirit by the printed "Cast this spell only during your end step". **badOwnedByAllPlayers** neighbours the printed "other players' graveyards"; **badUntapCapThree** sits one notch above the printed "can't untap more than two permanents".
5. Highest-value phase-2 widenings, in order: `deonticPatientOk` (one printed line already refused), `eventUse` + `triggerWordOk` (12 pins between them, all attestation), `partUse` + `spanUse` (8 pins), `negatable` and `possessorOk` (7 pins), then the count vocabularies `CapBound`/`NextUntapCount`/`capSubjectOk` (3). No pin was left UNCLEAR; the only genuinely contestable classification is **badCastInGraveyard**, which turns on a modelling choice (does `CastBy` seed the stack, or is "you cast" historical?) rather than on a rule.
